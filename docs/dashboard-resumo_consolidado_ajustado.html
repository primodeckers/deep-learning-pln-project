Análise

1. O problema e por que importa

Editais de licitação descrevem, em linguagem jurídica, o que o governo compra. Ler centenas manualmente para responder “em que áreas o governo gasta?” é inviável.

Coletamos dados inéditos (sem bases prontas de Kaggle): 423 editais do ComprasNet DF/2025, via HTML de detalhe — o PDF exigia CAPTCHA, que não foi contornado por ética.

2. A lição metodológica (o gancho)

A pergunta “deep learning vence sempre?” tem resposta: depende.

  • Com ~295 exemplos, TF-IDF + LogReg (0,74) supera BERTimbau (0,40).
  • Com ~14k exemplos, BERTimbau (0,858) inverte o resultado.
  • O SVM superou na validação mas overfitou (64 exemplos) — val ≠ teste importa.

3. Transparência > métrica bonita

Vazamento de label: usar o HTML completo inflava o F1 para ~0,88, porque o texto repete o nome do órgão (origem do rótulo). Trocamos para objeto_html → F1 honesto ~0,74.

Label proxy: o rótulo vem do órgão por keyword, validado por humanos com 83,2% de concordância — não é anotação manual perfeita, e declaramos isso.

4. Limitações e próximos passos

  • Corpus pequeno: Educação tem só 2 exemplos no teste → F1 instável.
  • ~48% das compras PNCP são lexicalmente vagas → classe Indeterminado e fallback órgão.
  • F1 ~0,97 nos protocolos de 9 setores = reprodução de regras, não generalização.
  • Próximos: anos 2021–2024; info complementar condicional; anotação manual parcial.

Síntese

Coletamos 423 editais do ComprasNet (DF 2025). O LogReg (F1 0,74) venceu SVM (0,65) e BERT (0,40) — corpus pequeno favorece o clássico. Estendemos para 19.944 compras do PNCP: o BERT (F1 0,858) venceu no protocolo honesto por órgão. A contribuição não é só a métrica, é explicar o que ela significa — vazamento documentado, label proxy validado, val vs teste separados.
